This intentionally replaces the heavier prompt/retrospective pipeline used in the author's other repos; the talk is the deadline.

- **2026-08-23** After twin needs `WolverineFx.RuntimeCompilation` (pinned 6.28.1, matching the Wolverine line): Wolverine 6 decoupled the Roslyn runtime compiler from core, so `TypeLoadMode.Dynamic` (the dev default we run everywhere, tests included) throws at startup without it. Referenced in `LayerCake.Slices.csproj`; auto-registers. Static/pre-generated codegen deliberately not adopted — one less moving part before the talk, and attendees who clone get the just-works path. Considered and rejected the mmo-reconnect hybrid (Dynamic in dev, Static + committed generated code in prod, Debug-gated package): its payoffs are production ones (image size, runtime-codegen memory) this repo doesn't have, and it imports a forget-codegen-write 404 failure mode plus committed codegen churn that would muddy the file-count slide. The production story is instead documented as a comment on the `WolverineFx.RuntimeCompilation` reference in `LayerCake.Slices.csproj`, pre-answering the "what about prod?" audience question.

- **2026-08-23** Slice 002 built end to end (change `slice-002-validate-coupon`); shared suite green on both hosts, 30/30 (18 from slice 001 + 6 coupon scenarios × 2 twins). Decisions made along the way:
  - **Per-twin clock sourcing** (per the change's design.md): the shared evaluation is `(Coupon?, DateTimeOffset now) -> CouponStatus` on both sides. After twin passes `DateTimeOffset.UtcNow` inline at the endpoint; before twin injects `IDateTimeProvider` (Application interface, Infrastructure implementation) into `CouponValidationService`. The ceremony asymmetry is the exhibit; tests need no time control because seed windows sit ±1 year/±1 day from now.
  - **Wire-status mechanics differ per twin, wire-identical result**: before twin's query handler maps the Domain `CouponStatus` enum to the contract string with an explicit switch (no JSON attributes in Domain); after twin's `CouponStatus` enum serializes itself via `JsonStringEnumConverter<T>` + `[JsonStringEnumMemberName]` (.NET 9+). Both emit exactly `invalid | notYetActive | expired | valid`.
  - **`percentOff` absent, not null**, via `[JsonIgnore(Condition = WhenWritingNull)]` scoped to the envelope DTO/record on both sides; the suite asserts the raw body never contains `percentOff` for non-valid statuses (and pins camelCase keys in the raw body, since `JsonSerializerOptions.Web` deserialization is case-insensitive).
  - **Coupon code is the after twin's Marten document identity** (`[Identity]` on `Code`, stored uppercase); lookup is one `ToUpperInvariant()` then `LoadAsync`. Before twin: Guid PK + unique index on uppercase `Code`. Deliberately NOT `[Entity]` on the after endpoint: the route value needs normalizing first, and a miss is the normal `invalid` answer, never a 404.
  - **`[Identity]` moved to the `JasperFx` namespace** in the JasperFx 2.0 line (Marten 9); it is no longer `Marten.Schema.IdentityAttribute`. Comment left at the use site.
  - **After twin `SeedData` moved** from `Cakes/SeedData.cs` to the project root (`LayerCake.Slices.SeedData`) since it now seeds two modules (cakes + coupons). Coupon seeding is a plain `Store` upsert (code = identity), so idempotency is by construction; verified both twins hold exactly three coupons after seeding twice.
